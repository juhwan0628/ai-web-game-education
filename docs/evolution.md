# Course Evolution

## Iteration 01 — Teaching Practicum

The first version optimized for fast classroom execution: teams described a small game, generated a single HTML file with Gemini, opened it in a browser, compared expected and actual behavior, and revised the result.

### Limitations observed

- Requirements lived mainly inside prompts.
- Team activity tended to concentrate around the coding step.
- Images and audio were difficult to manage as first-class assets.
- Single-file output was convenient but structurally limited.
- Submission handling required manual work.

## Iteration 02 — AI Education Course

The second version moved to a SPEC-driven workflow.

- SPEC.md became the shared source of truth.
- Development, visual design, and audio became explicit roles.
- Images and audio became local project assets.
- README.md documented execution and intent.
- Teams tested results against the agreed specification.
- Submission structure was validated automatically.
- Import and metadata updates were automated.

The main improvement was not simply using more AI tools. It was creating a workflow where requirements, responsibilities, and validation were explicit.
